# Prior art: what others building agent access to machines do, and what bears a second look

**Status:** a research note, **not a decision.** Under AGENTS.md rule 6, nothing here changes
what nervus does. Each entry flags an idea someone else has worked through, so whoever next
works on that part of nervus knows it exists. Where an entry says "bears a second look", that
is a suggestion for the session doing that work, which brings it to the operator as an ADR
question like any other.
**Date:** 2026-10-15
**Rewritten:** 2026-10-17, under AGENTS.md rule 11, to name no installation; nothing in its
findings changed.
**Asked for by:** the operator, 2026-10-15: is nervus novel next to what already exists, and
what can it learn from the rest? The measure is nervus's purpose: make it easy and safe to
give any agent a clear MCP connection for doing real work on your own machines.
**Method:** web searches and project pages read on 2026-10-15 by a Claude Code session. **No
project below was installed or tested.** Feature claims come from each project's own page or
README. Most of the commercial sources are vendors describing their own products. nervus's
side of each comparison was read from this repository on the same day, with the file named.

## The short answer to "is nervus novel"

None of its parts is new. Each piece exists somewhere. The combination, and the reasoning
behind it, does not seem to exist anywhere else.

- **SSH MCP servers** are plentiful (dozens on Glama and mcpservers.org). Almost all run on
  your own machine, one copy per AI client, using your own SSH keys. None found is a shared
  bastion (a single front door every agent goes through) holding its own credential.
- **Enterprise MCP gateways** (MintMCP, agentgateway, AWS's MCP Gateway Registry, Britive)
  make the same arguments as ADR-0001: each agent gets its own identity, credentials stay at
  the gateway, every call is attributed. But they front SaaS tools, not shells on machines.
- **Teleport** is the mature version of the idea at company scale. It treats agents as
  identities with short-lived certificates and offers MCP access with role-based controls.
  It is a whole identity platform to run.
- **Agent sandboxes** (agentic-sandbox, stereOS, SmolVM) make throwaway VMs on runtimes of
  their own, not on a hypervisor you already have.

What none of them combines: a self-hosted, single-operator bastion, with nothing installed on
targets, where the limit is enforced by the target rather than by filtering commands, with
background jobs that survive restarts, an independent witness in each target's `sshd` log
(ADR-0005), and an off switch whose scope is chosen in the moment (ADR-0003).

## Ideas that bear a second look

### 1. Show each client only the tools it can use

- **Elsewhere:** Britive and other MCP gateways filter tools per identity, so an agent never
  sees a tool it isn't entitled to.
- **nervus today:** the `proxmox` tool is present for every client whenever nervus is started
  with `--proxmox` (`src/nervus/server.py`, "Unconfigured means absent"). A token whose
  allowlist excludes the Proxmox host still sees the tool and is refused when it uses it. `hosts` already tells each client what it may reach.
- **Why it might matter:** nervus aims to give a *clear* connection. A tool the agent can
  never use costs tokens in every session's tool list and invites a refused call.
- **Bears a second look:** yes, small. The check before each call stays the boundary. Hiding
  a tool only tidies the list and is not security. One catch: clients cache the tool list for
  a session, so a token's reach changed mid-session would still need the refusal.

### 2. A middle access level, enforced by the target

- **Elsewhere:** python-ssh-mcp has four tiers, each off by default: read, low-access,
  dangerous, sudo. It enforces them inside the MCP server, which ADR-0001 s5 rejects.
- **nervus today:** ADR-0005 decision 5 offers two levels per host, chosen at enrollment:
  read-only (an SSH *forced command*, a key that can only run one fixed program) or full
  (`agent` with passwordless sudo).
- **Why it might matter:** python-ssh-mcp's insight is that most real work needs a shell but
  not root. A level in between, a full shell as `agent` with *no* sudo, can be enforced by the
  target alone, through `/etc/sudoers`. nervus would hold no more power than the host gave
  it, so it is a boundary, not a policy, in ADR-0005's own terms.
- **Bears a second look:** yes, when enrollment levels are next designed (ADR-0005 decision
  5, ADR-0011 decision 3). Keep the vocabulary, enforce it the nervus way.

### 3. Uploads: atomic writes, and files that don't pass through the model

- **Elsewhere:** python-ssh-mcp writes files over SFTP *atomically*: it writes to a
  temporary name, then renames, so a file is either the old version or the whole new one.
  Upload tools take a path on the client's own disk and stream the file, instead of the
  model carrying it as base64 text.
- **nervus today:** `put` copies straight to the final path (`src/nervus/sftp.py`,
  `put_file`), so an interrupted transfer leaves a partial file where the real one should be.
  Most agent uploads skip `put` entirely and send the file inside an `exec` command, which
  makes up 73% of the audit log (ADR-0013's reading, cited in `CURRENT_STATE.md`).
- **Bears a second look:** yes, in the uploads ADR, which is next after ADR-0017. ADR-0016
  already built half of the second idea for downloads.

### 4. Pre-filling enrollment from the user's SSH config

- **Elsewhere:** Remote SSH MCP discovers host aliases from `~/.ssh/config` and offers them
  as its allowlist.
- **nervus today:** enrollment is a command the user runs as root on each new machine
  (ADR-0011 decision 3). That is deliberate: the person at the machine chooses its level, and
  nervus never borrows the user's own keys.
- **Bears a second look:** maybe, and only as a convenience. Reading names and addresses to
  pre-fill the enrollment page could save typing. Using the config's keys would undo the point
  of nervus, so that part is not a candidate.

### 5. nervus as the front door for other MCP servers

- **Elsewhere:** Teleport and the MCP gateway registries put *other* MCP servers behind
  them: one connection for the agent, one identity check, one audit log for everything.
- **nervus today:** it fronts SSH and the Proxmox API. ADR-0001 s9 lists other services' APIs
  and a log store as deferred tools of its own.
- **Bears a second look:** maybe, later, and **it is a scope question for the operator, not
  for a session.** It fits "one clear connection" and modularity. It also means trusting
  third-party servers' code inside the trust domain ADR-0007 decision 9 describes.

### 6. Running one command across a group of hosts

- **Elsewhere:** mcp-ssh-orchestrator runs a command across hosts selected by tag.
- **nervus today:** one host per `exec`. `hosts.yaml` has a free-text `role` but no tags.
- **Bears a second look:** low. An agent can loop, and each host keeps its own audit record.
  A group command widens what one call can break. Worth reconsidering if a published nervus
  has users with many identical machines.

## Considered and not a fit, recorded so they aren't reopened

- **Filtering commands by text** (mcp-ssh-orchestrator's `deny_substrings`, which blocks any
  command containing `curl ` or `reboot`; python-ssh-mcp's per-host command allowlist).
  Rejected by ADR-0001 s5 and ADR-0007 decision 1: `bash -c` and an encoded payload get
  around it. The orchestrator's own example shows why. It blocks `curl ` with a trailing
  space. If it matches plain text, as its name suggests (this note did not check its code),
  `curl` followed by a tab gets through.
- **Shells that stay open between calls, keeping their directory and environment** (sshmcp,
  Remote SSH MCP). Each nervus `exec` starts fresh and takes `cwd`. That keeps every audit
  record self-contained. In a persistent shell, an earlier `cd` or `export` silently changes
  what a later command means, and the audit record of the later one doesn't show it.
- **Storing commands as hashes in the audit log** (python-ssh-mcp). nervus records commands
  in full, because seeing who ran what is the log's purpose (ADR-0001 s10).
- **Jump hosts and proxy chains** (firstfinger/ssh-mcp, python-ssh-mcp). ADR-0005 decision 2
  answers reachability with an overlay network beneath SSH, and says so "so it is not
  relitigated". A jump host also stays within SSH and needs nothing installed on targets, so
  it would not conflict with that reasoning if a published user ever needed one. Noted for
  awareness only.
- **Proxmox: leaving destroy out of the tool, or typed tools such as `clone_vm`** (some
  community Proxmox MCP servers). ADR-0009 decision 2 makes Proxmox's own permissions the
  boundary and rejected curated `proxmox_*` tools. ADR-0017 question L weighs typed tools
  again for VMs. Linked clones, templates and guest-agent IP lookup, all common elsewhere,
  are already in ADR-0017.
- **Keystroke-level session recording** (Teleport, Britive). nervus has no interactive
  sessions to record. Each call's command, bounded output and full output on the target's
  disk serve that purpose.

## Where nervus already matches or leads, for the record

- **A separate credential for each agent, revocable without touching the others** (MintMCP):
  ADR-0001 s6 and ADR-0003's per-client switch.
- **Credentials held at the gateway, never by the agent** (Britive, the AWS registry):
  ADR-0001 s2 and s3.
- **Short-lived credentials** (Teleport, Snowflake's guide): ADR-0006 proposes OAuth 2.1 with
  short-lived access tokens. Teleport confirms the direction. Nothing new to add.
- **Logging refused attempts, not just successes** (Snowflake): `record_refusal` in
  `src/nervus/audit.py`.
- **The model cannot read its own audit trail** (python-ssh-mcp): ADR-0005 decision 4.
- **One id linking each call's intent to its result** (python-ssh-mcp's `correlation_id`):
  the `run_id` in `src/nervus/audit.py`.
- **Background jobs that survive a restart**: python-ssh-mcp's tasks are lost unless Redis is
  added. ssh-mcp-rs says its jobs are not guaranteed to survive. nervus's run in tmux on the
  target (ADR-0001 s9, acceptance item 3).
- **Packaged as a container with YAML configuration** (mcp-ssh-orchestrator): ADR-0005
  decision 1.

## One naming caution

`mcp-bastion` (github.com/Gowthaman90/mcp-bastion) is an unrelated MCP security proxy. Any
public description of nervus as "an MCP bastion" will share search results with it.
ADR-0005 decision 6 kept the name, and this doesn't change that.
